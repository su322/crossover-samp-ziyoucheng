## J.3 根因：域名有 4 条 A 记录

`USERDATA.DAT` 里记的是**域名**而不是 IP：

```
$ xxd ~/Documents/GTA\ San\ Andreas\ User\ Files/SAMP/USERDATA.DAT
00000000: 5341 4d50 0100 0000 0100 0000 0e00 0000  SAMP............
00000010: 6473 2e7a 7963 646a 7a31 2e63 6f6d 611e  ds.zycdjz1.coma.
00000020: 0000 1700 0000 a1ef 4472 6966 7420 5374  ........Drift St
00000030: 6172 a1ef d7d4 d3c9 b3c7 3120 2d00 0000  ar........1 -...
00000040: 0000 0000 00                             .....
```

结构：

| 偏移 | 内容 |
|---|---|
| `0x00` | `"SAMP"` magic |
| `0x04` | 版本 `1` |
| `0x08` | 收藏服务器数量 `1` |
| `0x0C` | 字符串长度 `14` |
| `0x10` | `"ds.zycdjz1.com"` |
| `0x1E` | 端口 `0x1E61` = **7777** |
| `0x22` | 字符串长度 `23` |
| `0x26` | `"★Drift Star★自由城1 -"`（GBK） |

注意 `0x1E` 那个 `61 1e` 很容易被误读成字符串的一部分——`strings` 会把它拼成 `ds.zycdjz1.coma`，别被带偏。

然后查这个域名：

```sh
$ dig ds.zycdjz1.com A +noall +answer
ds.zycdjz1.com.		1453	IN	A	154.12.58.56
ds.zycdjz1.com.		1453	IN	A	154.12.58.26
ds.zycdjz1.com.		1453	IN	A	154.12.58.112
ds.zycdjz1.com.		1453	IN	A	45.158.21.28
```

**4 台不同机器，轮询返回**（连查三次，顺序每次都变）：

```
第1次: 154.12.58.26 45.158.21.28 154.12.58.112 154.12.58.56
第2次: 45.158.21.28 154.12.58.112 154.12.58.56 154.12.58.26
第3次: 154.12.58.26 154.12.58.56 154.12.58.112 45.158.21.28
```

所以：

1. 浏览器里那条收藏是**域名**，每次打开都重新解析；
2. 解析到哪台，就查哪台的在线人数；
3. 4 台人数各不相同 → **每次看到的数字都不一样，看起来就是"显示不对"**；
4. 倒霉解析到 `45.158.21.28` 时，如果那台正好在维护/更新，就出现 `The server didn't respond`（本次就是这个情况）。

这跟 msync、跟 `0x0053388E` 补丁、跟渲染后端**都没有关系**。

## J.4 顺带排掉的错误假设

| 假设 | 结果 |
|---|---|
| msync 关闭导致人数错乱 | ❌ 附录 I 作废，恢复 `1` 后照样错 |
| 残留 wineserver 继承了旧 `WINEMSYNC` | ⚠️ 确实存在（5 个残留进程），已全部清掉，但不是本因 |
| 游戏文件被改动 | ✅ 已复验，SHA-256 与补丁字节完全一致 |
| 沙箱拦截 UDP 出网导致探测全超时 | ❌ 已排除：UDP :53、:123、:19302 全部正常，是那几台节点**真的不答直连查询** |

残留进程清理命令（仅 `samp` bottle，不影响 `Steam` bottle）：

```sh
pgrep -fl "winedevice|wineserver|winewrapper"
lsof -p <pid> | grep Bottles/          # 确认归属哪个 bottle
wine --bottle samp --cx-app 'C:\windows\system32\wineboot.exe' --kill
```

`WINEMSYNC` 只在 **wineserver 启动时读一次**，所以改完 `cxbottle.conf` 必须把整个会话杀掉重开，否则新进程会挂到旧 wineserver 上继续用旧值。

## J.5 解决办法

**别用域名收藏，用 IP 收藏。**

在 SA-MP 的 Favourites 里手动添加：

```
154.12.58.112:7777
```

这样：

- 永远连到同一台，人数稳定且正确；
- 不会再随机落到别的节点，也就不会因为"那台在维护"而连不上；
- 代价是服务器换 IP 时要手动改一次。

想省事也可以四条都加上，按需选：

```
154.12.58.112:7777
154.12.58.26:7777
154.12.58.56:7777
45.158.21.28:7777
```

## J.6 阶段性教训（写于结案前，结论见 J.8）

排查这类"配置改了但行为没变"的问题，**先看 chatlog 里实际连的 IP**，再看配置。域名轮询这种坑，光盯着 Wine 配置是永远查不出来的。

## J.7 补充：直连查询被拒，浏览器人数其实来自主列表

自己写 SA-MP 查询包（`"SAMP"` + 4 字节 IP + 2 字节端口，发 UDP 7777）去打这 4 个 IP，**全部超时**。

先怀疑是沙箱拦 UDP，逐个排除：

| 测试 | 端口 | 结果 |
|---|---|---|
| DNS 查询 | UDP 53 | ✅ 通（22ms） |
| NTP | UDP 123 | ✅ 通（55ms） |
| STUN Binding | UDP 19302 | ✅ 通（209ms） |

高位端口明明放行，所以结论是：**这几台服务器拒绝来自非白名单来源的直连查询**（国内服常见的防扫描 / 游戏盾策略）。

由此可以推出一个容易忽略的点：

> SA-MP 0.3.7 的服务器浏览器人数，主要来自 **master 列表的定期扫描快照**，不是你自己直连查的实时值。

所以"人数显示不对 / 骤减"还有第三种可能：**master 扫描失败导致快照过期**，界面上的数字停在一个旧值上。

区分办法：

| 现象 | 判断 |
|---|---|
| 刷新几次，数字在几个值之间**大幅跳变** | 轮询 DNS 换了节点（见 J.3） |
| 数字**稳定但明显偏低**，进游戏后按 TAB 人数却很多 | master 快照过期 |
| 数字**稳定偏低**，进游戏 TAB 也少 | 服务器真的没人（时间点 / 刚重启） |

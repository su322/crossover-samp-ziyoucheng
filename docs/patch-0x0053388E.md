# 附录 E：`0x0053388E` 崩溃与路牌空指针补丁（2026-11-01 已安装）

> 原 README 附录 E · 拆分于 2026-11-01 · [← 返回正文](../README.md)

## E.1 崩溃特征

- 报错：`Unhandled exception at 0x0053388E`，`0xC0000005`，读取地址 `0x00000004`。
- 寄存器：`EAX=0`、`EBX=0`。
- 发生时机：进服后偶发“卡一下然后闪退”，不固定地点；常出现在模型流式加载阶段。
- 反汇编：

```
0x533887  call 0x6FF2D0      ; CCustomRoadsignMgr::CreateRoadsignAtomic
0x53388C  mov  ebx, eax      ; 返回 NULL
0x53388E  mov  edi, [ebx+4]  ; 读 0x00000004 -> 崩溃
```

`CEntity::CreateEffects`（`0x533790`）处理 2D 效果类型 7（roadsign）时，没有检查 `CreateRoadsignAtomic` 的返回值。材质、纹理、几何体或 atomic 创建失败时该函数返回 `NULL`，调用方随后直接解引用。

## E.2 为什么不是内存不足 / 字体

- 崩溃时 `gta_sa.exe` physical footprint 约 320.5 MB，peak 约 434.7 MB，不像是 32 位地址空间耗尽。
- 扫描本地 `.ide`：97 条 type 5 2dfx，0 条 type 7 roadsign；`SAMP.ide` 的 `2dfx` 段为空。
- 因此触发源大概率是服务器自定义地图/对象，而不是本地字体或标准数据。字体实验已全部回滚，与本崩溃无关。
- SAMP Addon 的更新日志也把 `0x0053388E` 列为 “if game can't create 2D effect”，可交叉印证。

## E.3 补丁内容

只改 5 字节入口，外加 31 字节 code cave（`.text` 里的零填充区）；不重定位、不改 PE 头、不动 `samp.dll`。

| 项目                | 值                                                                                              |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| 入口 VA / 偏移        | `0x53388C` / `0x132C8C`                                                                        |
| 原始字节              | `8B D8 8B 7B 04`                                                                               |
| 补丁字节              | `E9 09 34 32 00`（`jmp 0x856C9A`）                                                               |
| Code cave VA / 偏移 | `0x856C9A` / `0x45609A`                                                                        |
| Cave 字节（31）       | `85 C0 74 0A 8B D8 8B 7B 04 E9 E9 CB CD FF 81 65 1C FF FF FF FE 33 DB 83 C4 04 E9 A1 CC CD FF` |
| 原版 SHA-256        | `a559aa772fd136379155efa71f00c47aad34bbfeae6196b0fe1047d0645cbd26`                             |
| 补丁后 SHA-256       | `6f2b7950c178dff0a1bb9aa513694b92b7bae35dc36586dca089bf618888b71b`                             |

逻辑：

1. `test eax,eax`；非 0 时执行原来的 `mov ebx,eax` / `mov edi,[ebx+4]`，跳回 `0x533891`，行为与未打补丁时完全一致。
2. 为 0 时清掉 `[ebp+0x1C]` 的 bit 24（`m_bHasRoadsignText`），`ebx=0`，`add esp,4` 平衡 `CreateRoadsignAtomic` 的参数，跳到 `0x53395A`。
3. `0x53395A` 处把 `effect->roadsign.m_pAtomic` 写回 `NULL` 并继续循环；`DestroyEffects`（`0x533C68`）本来就会对 `m_pAtomic` 判空，因此安全。

## E.4 验证状态

- 2026-11-01 打补丁后启动 `samp.exe` 直连 `154.12.58.112:7777`，能正常进服，未再出现同一地址崩溃。
- 非空分支每次创建路牌都会走到，正常游玩未见异常。
- “返回 NULL”分支无法按需触发（触发源在服务器地图里），所以这次只验证了补丁不破坏正常流程，不能证明那个坏路牌本身已修好；最坏情况是该路牌不显示文字，而不是闪退。
- 若之后仍在 `0x0053388E` 崩溃，说明补丁未生效或被其他文件覆盖，先核对 `gta_sa.exe` 的 SHA-256。

## E.5 重新打补丁

先备份原版 `gta_sa.exe` 为 `gta_sa.exe.orig`，然后在游戏目录运行：

```python
#!/usr/bin/env python3
"""GTA SA 1.0: null-check CCustomRoadsignMgr::CreateRoadsignAtomic at 0x53388C."""
import hashlib
import pathlib
import struct
import sys

PATCH_VA = 0x53388C
CAVE_VA = 0x856C9A
RET_NORMAL = 0x533891
RET_NULL = 0x53395A
PATCH_OFF = 0x132C8C
CAVE_OFF = 0x45609A

path = pathlib.Path(sys.argv[1] if len(sys.argv) > 1 else "gta_sa.exe")
data = bytearray(path.read_bytes())
current = bytes(data[PATCH_OFF:PATCH_OFF + 5])

if current == b"\xE9\x09\x34\x32\x00":
    print("already patched:", path)
    sys.exit(0)
if current != bytes.fromhex("8B D8 8B 7B 04"):
    sys.exit(f"unexpected bytes at {PATCH_OFF:#x}: {current.hex()}")
if any(data[CAVE_OFF:CAVE_OFF + 31]):
    sys.exit(f"code cave not empty at {CAVE_OFF:#x}")

cave = b""
cave += bytes.fromhex("85 C0")                 # test eax,eax
cave += bytes.fromhex("74 0A")                 # jz cave+0x0e
cave += bytes.fromhex("8B D8 8B 7B 04")        # original two instructions
cave += b"\xE9" + struct.pack("<i", RET_NORMAL - (CAVE_VA + 14))
cave += bytes.fromhex("81 65 1C FF FF FF FE")  # and [ebp+0x1C], ~0x01000000
cave += bytes.fromhex("33 DB")                 # xor ebx,ebx
cave += bytes.fromhex("83 C4 04")              # add esp,4
cave += b"\xE9" + struct.pack("<i", RET_NULL - (CAVE_VA + 31))
assert len(cave) == 31

patch = b"\xE9" + struct.pack("<i", CAVE_VA - (PATCH_VA + 5))
data[PATCH_OFF:PATCH_OFF + 5] = patch
data[CAVE_OFF:CAVE_OFF + 31] = cave
path.write_bytes(data)

print("patched:", path)
print("sha256:", hashlib.sha256(data).hexdigest())
```

打完后的 SHA-256 应为 `6f2b7950c178dff0a1bb9aa513694b92b7bae35dc36586dca089bf618888b71b`。

还原：用 `gta_sa.exe.orig` 覆盖 `gta_sa.exe`，确认 SHA-256 回到 `a559aa77...`（见第 7 节第 5 条）。
